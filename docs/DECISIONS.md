# Architecture Decisions

Decisions that shape Plan F, recorded so they are not re-argued by accident.
Each entry: what was decided, why, and when to revisit. THIS PHASE DOES NOT
ACTIVATE PLAN F: entries D-PLANF-001 to D-PLANF-012 describe the target
design; only the contracts, base class, registry and inactive budgets exist
in code today.

## D-PLANF-001 Plan F is a findings-based two-layer architecture
- Date: 2026-09-24
- Decision: a Coordinator selects domain specialists; each specialist returns structured findings (claim, evidence quote, source, page, confidence) rather than a final answer; the orchestrator renders or aggregates the findings and the Verifier checks them.
- Why: a specialist that writes the final answer cannot be verified against its evidence, and its prose cannot be combined with another specialist's without losing source boundaries. Findings keep every statement traceable to a source.
- Revisit: if the Teaching Agent gate shows findings add latency without improving verifiability.

## D-PLANF-002 The Coordinator owns routing and decomposition
- Decision: one component decides domains, level, systems, selected specialists and subtasks. It reuses the existing Router for technical intent and adds domain scoring; one structured LLM call is allowed only for ambiguous, multipart or cross-domain questions.
- Why: two competing classifiers would disagree; a deterministic-first Coordinator keeps simple questions at zero LLM calls, as the Router does today.
- Revisit: after domain-accuracy measurement on the labelled set.

## D-PLANF-003 Four specialists, no more
- Decision: `teaching`, `research`, `faculty_services`, `institutional`, centralised in `SpecialistId`.
- Why: they match the handbook's chapter structure and the sources the team can obtain. Every candidate for a fifth (Orientation, Blackboard, Banner, College, Department) either owns no unique decision or is a knowledge source.
- Revisit: only with evidence that a candidate owns decisions none of the four can make.

## D-PLANF-004 Specialists never call each other; the orchestrator executes handoffs
- Decision: a specialist that needs another domain returns a `HandoffRequest`; the deterministic orchestrator validates and executes it.
- Why: direct calls make budgets unenforceable, hide loops, and make traces incomplete.
- Revisit: never; this is a safety property.

## D-PLANF-005 Maximum handoff depth is one round
- Decision: `PLAN_F_MAX_HANDOFF_DEPTH = 1`. Requests produced by the handoff round are recorded, not executed.
- Why: bounded latency and cost; every collaboration case in the candidate set is satisfied by one round.
- Revisit: if reviewed cases show a required second round.

## D-PLANF-006 The orchestrator stays deterministic Python
- Decision: no LLM decides control flow, parallelism, budgets or retries.
- Why: testable, reproducible, and the same reason Milestone 1 rejected an LLM manager.
- Revisit: never.

## D-PLANF-007 One shared, scope-aware evidence retrieval
- Decision: one FAISS index over all approved sources; a hard source-scope filter per specialist; soft system and domain boosts.
- Why: four indexes would quadruple build time and cache size for no retrieval benefit; scope is a filter, not a separate store.
- Revisit: only if benchmarking shows scoped retrieval quality suffers in a shared index.

## D-PLANF-008 Plan F budgets are declared now and inactive
- Decision: `PLAN_F_ENABLED = False` and `PLAN_F_MAX_*` constants exist in `config.py`; the Milestone 1 pipeline keeps `MAX_LLM_CALLS = 2` and `MAX_VERIFY_RETRIES = 1`.
- Why: raising the live budget before the Coordinator exists would change Milestone 1 behaviour and its measured cost for no benefit. Namespacing avoids two meanings of one name.
- Revisit: when the Plan F orchestration path is wired in, `PLAN_F_ENABLED` becomes the switch.

## D-PLANF-009 The Verifier stays independent and gains a findings mode later
- Decision: the existing sentence-level Verifier remains; a later phase adds quote-in-source, claim-supported-by-quote, subtask coverage, citation origin and conflict checks. It trusts no specialist.
- Why: the Milestone 1 rules already prevent invented citations; findings mode extends them without replacing them.
- Revisit: at the Teaching Agent gate.

## D-PLANF-010 Synthesis is used conditionally
- Decision: one supported specialist on a simple question is rendered deterministically without an LLM; several specialists, multipart or partial results go through Synthesis in an aggregation mode that receives structured findings only.
- Why: the common case stays at one LLM call; aggregation is needed only when findings must be combined.
- Revisit: if deterministic rendering reads poorly in acceptance testing.

## D-PLANF-011 Blackboard and Banner are systems and sources, not agents
- Decision: the Teaching & Learning specialist owns them; their guides are ingested as sources with a `system` tag.
- Why: they own no decision; a "Blackboard agent" would be retrieval with a label.
- Revisit: never.

## D-PLANF-012 Orientation is a Coordinator journey mode
- Decision: an orientation question makes the Coordinator select specialists in stage order and Synthesis render an ordered checklist. No Orientation specialist.
- Why: orientation is a sequence over the other domains, not a domain.
- Revisit: only with evidence that orientation owns decisions the Coordinator cannot express.

## D-PLANF-013 Contracts are plain dataclasses with self-validation
- Decision: `contracts.py` uses `@dataclass` with `__post_init__` validation and `to_dict()`, and `str` enums for ids and statuses; no Pydantic, no new dependency.
- Why: matches `agents/types.py`; Pydantic is only a transitive dependency of the Groq SDK and the project does not use it.
- Revisit: if a later phase needs schema export for the Coordinator's structured LLM call.

## D-PLANF-014 QAResult is not extended in the foundation phase
- Decision: no Plan F fields are added to `QAResult` until a runtime component produces them.
- Why: fields with no producer cannot be tested for meaning, and every addition touches `to_dict()`, the UI and the run files.
- Revisit: in the first phase that returns a `CoordinatorDecision` or `SpecialistFindings` through `answer_question()`.

## D-PLANF-015 The Coordinator is deterministic-first and built on the Router
- Date: 2026-09-24
- Decision: `agents/coordinator.py` takes technical intent, the multipart flag and route scores from the existing Router with its LLM arbitration switched off, and adds domain, level, system and complexity classification from cue lexicons. The Router is not modified or duplicated.
- Why: two intent classifiers would disagree; the Router already handles the route vocabulary and its regression suite; the Coordinator only adds what the Router does not know (domains, levels, systems, specialists).
- Revisit: if domain accuracy on the labelled set shows the cue lexicons need a different mechanism.

## D-PLANF-016 Domain, level and system rules are cue lexicons with conditional overrides
- Decision (amended 2026-09-24 after review): each domain has strong cues (1.0) and hints (0.5); a domain is a candidate at 1.0. Level is the most specific of department, college, university. Systems are blackboard, banner, myuos. Contact questions are conditional: a direct channel lookup (phone, fax, e-mail address, extension, "number of the") selects Institutional Navigation alone; a contact request about a subject keeps the subject specialist(s) and adds Institutional. A bare Blackboard or Banner mention selects Teaching, which owns those guides; a bare MyUOS mention selects nobody, because MyUOS is the general portal. Rules are documented in `docs/COORDINATOR.md`.
- Why: transparent, testable and cheap; the vocabulary is routing language, not policy content. The first version selected Institutional alone for every contact route and gave MyUOS to Teaching; review showed both erased or fabricated the subject domain.
- Revisit: after measuring domain accuracy; hints and weights may change without touching the contract.

## D-PLANF-017 One task per selected specialist, full question plus focus, synthesis by rule
- Decision (amended 2026-09-24 after review): candidates are capped at `min(PLAN_F_MAX_SPECIALISTS, PLAN_F_MAX_SUBTASKS)`; each selected specialist receives one task whose `question` is always the complete original question, with the specialist's own clauses in `context["focus_clauses"]` (shared clauses allowed, dropped-domain clauses reported as uncovered, whole question as focus when no clause is its own); `requires_synthesis` is True for two or more specialists or a single-specialist multipart question, never for the journey label alone.
- Why: a clause fragment such as "who approves it" cannot be answered on its own; the full question keeps every task self-contained while the focus tells the specialist its part. The count stays bounded and the Verifier can check coverage against explicit tasks and uncovered clauses.
- Revisit: if the Teaching Agent gate shows specialists need a different focus representation.

## D-PLANF-018 Coordinator LLM arbitration is deferred
- Decision: no LLM call in the Coordinator; `used_llm` is always False.
- Why: the Router must pick exactly one route, so a tie needs a tie-breaker; the Coordinator may select several specialists when domains tie, and the orchestrator, Synthesis and the Verifier reconcile their findings. An arbitration call would only save the cost of an extra specialist run, which is a measurement for the Teaching Agent gate, not a design need today.
- Revisit: at the Teaching Agent gate, with measured specialist-call counts on cross-domain questions.

## D-PLANF-019 Unknown questions select nobody; the Coordinator stays inactive
- Decision: a question with no domain cue and no system gets no specialist, confidence 0.0 and complexity `unknown`, so the future orchestrator can fall back to the Milestone 1 handbook path; a greeting gets no specialist; orientation questions are classified as `journey` but not routed by stage. The Coordinator is not wired into `answer_question`, the orchestrator, the UI or the evaluation runtime, and `PLAN_F_ENABLED` remains False.
- Why: a fabricated domain decision on nonsense would send a specialist to answer something it cannot ground; the handbook path already refuses safely. Activation is a separate, reviewable phase.
- Revisit: when the Plan F orchestration path is built.

## D-PLANF-020 Coordinator confidence is a heuristic ordinal; decision metadata has one shape
- Date: 2026-09-24
- Decision: `CoordinatorDecision.confidence` is a heuristic ordinal signal for ordering and traces (formula in `docs/COORDINATOR.md`); it is not calibrated, not a probability and not a measured accuracy, and no document or report may present it as such. Every decision, greeting and empty question included, carries the same `metadata` keys (`METADATA_KEYS`), with empty values where nothing applies.
- Why: a number without calibration invites false precision in the report; a uniform metadata shape lets the orchestrator and the UI read decisions without special cases.
- Revisit: if routing accuracy is measured and a calibrated score becomes available.

## D-021 One source registry and per-source section maps instead of a heading heuristic
- Date: 2026-09-28
- Decision: documents the corpus may be built from are declared in `knowledge/sources.json` (`handbook_bot/sources.py`); the handbook's chapters and level-2 sections are a page-range map in `knowledge/handbook_sections.json`, derived from the document's own table of contents and checked heading by heading. The loader's heading guess (`section`, "Page N" on almost every page) stays untouched and unused.
- Why: source-scoped retrieval needs a stable source identity and a reliable section label on every chunk; the table of contents is authoritative and machine-checkable, the heuristic is not. Repository-relative paths keep the registry portable across machines.
- Revisit: when a second document is added (a second map file, same schema) or if a finer, level-3 map is needed.

## D-022 Section ranges share boundary pages; a page carries all its sections plus one primary
- Decision: ranges are inclusive and a section may share its first page with the section that ends there. `page_section_nos` lists every section on the page; `section_no` is the first section starting on the page, otherwise the one in progress. Section scoping matches any section present on the page.
- Why: page-granular metadata cannot split a page; excluding boundary pages would lose real content (the academic calendar continues onto page 51, where 1.15 starts; page 222 holds 12.10, 12.11 and 12.12). Recall at the boundary is preferred, the reranker and the Verifier decide relevance.
- Revisit: if chunk-level heading detection is ever added.

## D-023 Document numbering quirks are recorded as printed, chapter comes from page ranges
- Decision: the handbook prints 5.2 and 7.8 twice and numbers the copyright policy in chapter 9 as 12.3. The map keeps the printed numbers with a note on each record; `chapter` is always derived from the chapter page ranges, never from the section number.
- Why: repairing the document's numbering would invent labels that do not appear in the source; deriving the chapter from pages keeps chapter and prefix scoping correct regardless.
- Revisit: only if a corrected handbook edition is issued.

## D-024 Retrieval scope is generic, optional and enforced at the index level
- Decision: `RetrievalScope` (source ids, chapters, exact section numbers, dotted section prefixes, page ranges) is an optional argument of `gather_candidates`. Dense search runs as an exact FAISS search restricted by an id selector over the allowed chunks; lexical search scores only allowed chunks; a scope matching nothing returns nothing. `scope=None` is the previous code path, pinned by a snapshot test.
- Why: post-filtering a global top-k can lose in-scope chunks that rank below the global cut-off, which would turn a scoped search into a silent miss; restricting at the index level cannot. Falling back to the whole corpus on an empty scope would defeat the purpose of scoping and is a hallucination risk, so it is forbidden. The scope names no domain and no specialist: those policies belong to later phases.
- Revisit: if a non-flat index type is adopted (the fallback scoring assumes an inner-product flat index).

## D-025 Cache version v12; no runtime component uses the new metadata yet
- Decision: `CACHE_VERSION` v11 to v12 because cached metadata changed; `EvidenceResult.doc_id` stays unpopulated and the orchestrator, Router, Synthesis, Verifier and UI are unchanged. Chunk metadata alone carries source identity for now.
- Why: the phase adds infrastructure only; wiring it into the pipeline is reviewed separately with the first consumer.
- Revisit: with the first component that passes a scope or reads `source_id`.

## D-026 Section metadata is source-faithful; section retrieval is chapter-consistent
- Date: 2026-09-28 (correction pass after independent review)
- Decision: chunk metadata records section numbers exactly as the document prints them, including the chapter-9 section printed as 12.3. `RetrievalScope` section and prefix constraints accept a printed number only when its leading number equals the chunk's resolved `chapter`, which comes from the chapter page ranges. `chapters={9}` with `section_numbers={"12.3"}` therefore matches nothing, by design; that section is reached by chapter or page range.
- Why: the review showed `section_prefixes={"12"}` admitting intellectual-property text from chapter 9. Rewriting the printed number would invent a label the source does not contain; matching by resolved chapter keeps source fidelity and closes the leak.
- Revisit: never for fidelity; the matching rule may change if a unique section-record identifier is introduced.

## D-027 Section scopes are page-granular and section numbers are not identifiers
- Decision: section constraints restrict pages associated with a section (every section present on the page counts) and do not isolate text on shared pages; `section_no` is metadata as printed and may repeat (5.2, 7.8). Callers prefer `source_ids` plus `chapters`, and page ranges where physical isolation matters.
- Why: 115 of 272 pages carry more than one section; text-level splitting would need reliable heading detection inside pages, which the loader does not provide. Documenting the contract is safer than implying a precision that does not exist.
- Revisit: if chunk-level heading detection or a unique section-record identifier is added.

## D-028 Registered-source identity is strict path identity; incompatible section maps are not applied
- Decision: `find_source_for_path` matches only the file at the registered repository-relative location, in any spelling (the operating system decides when both files exist); a same-named file elsewhere is unregistered. A section map is applied only when the loaded page count and highest page index equal its `page_count`; otherwise the source keeps its identity, chunks get no section labels, and a warning is printed.
- Why: the file-name fallback let any same-named file claim the handbook's identity, and a different edition would have received wrong section labels silently. Length is a cheap, model-free edition check; content fingerprinting is deferred.
- Revisit: when a size or hash field is added to source records.

## D-029 Scoped dense fallback supports inner-product indexes only and never masks search failures
- Decision: the id-selector path is tried first; the direct-scoring fallback runs only when the index cannot take search parameters (`TypeError`, `AttributeError`) and only for an index whose `metric_type` is inner product; any other metric raises `TypeError`. A `RuntimeError` from the index propagates.
- Why: scoring an L2 index as inner product would return misleading similarities; catching `RuntimeError` hid genuine failures behind a fallback.
- Revisit: if a non-flat or non-inner-product index is adopted.

## D-030 The first specialist is deterministic and extractive
- Date: 2026-09-28
- Decision: `TeachingLearningSpecialist` makes no LLM call. Every finding's claim is the quoted handbook text and the quote is an exact slice of a retrieved chunk; source id and page come from chunk metadata. Synthesis remains the only place where user-facing prose is written.
- Why: the specialist is the architecture proof; removing generation from it removes the possibility of invented facts while the contract, scoping, status rules and handoffs are validated. A future reasoning step, if measurements justify one, would sit behind the same quote-validation rule.
- Revisit: at the Teaching QA gate, with measured evidence quality on the real index.

## D-031 Teaching scope is a curated list of sections compiled to page ranges
- Decision: the specialist owns the sections in `OWNED_SECTIONS` (chapter and printed number), compiled from the section map into `RetrievalScope(source_ids, page_ranges)` at construction. Chapter 5 is not taken whole: 5.4 (conferences) is excluded. Ambiguous areas (2.9, 3.5, 3.6, 6.2, 6.3, 12.8 to 12.11, 12.19, 12.20) are excluded and listed in `EXCLUDED_SECTIONS`.
- Why: ownership must follow the text, not chapter titles; excluding an ambiguous area costs recall on a few questions, including one costs leakage of another specialist's material. Compiling from the map keeps the scope in step with the document and fails loudly when a section is missing.
- Revisit: after the Teaching QA gate, section by section, with recorded evidence.

## D-032 Scope eligibility is not evidence; relevance and the gate decide
- Decision: a chunk inside the scope becomes a finding only when it passes `MIN_RERANK_SCORE` (applied to every kept item) and one of its sentences shares at least one stemmed content word with the focus clause; the quote is that sentence, extended by the next when it also matches.
- Why: section labels are page-granular, so an included page may carry a neighbouring section's text. The one-word rule is a simple, documented relevance filter, not a calibrated threshold, and the existing gate is reused rather than a new number invented.
- Revisit: when the cross-encoder's behaviour on scoped candidates has been measured.

## D-033 System procedures are never generated
- Decision: a clause asking for a step-by-step procedure in Blackboard, Banner or MyUOS is at most `partial`; policy evidence is returned, `missing` names the absent procedure and `limitations` states that no procedural guide is indexed. Fact questions about a system ("how do grades reach Banner") may be `supported`.
- Why: the corpus contains policy references only; anything more would be invented.
- Revisit: when verified guides are registered and indexed.

## D-034 Specialists reason over assigned clauses only and never re-route
- Decision: the specialist works on `task.context["focus_clauses"]` (the whole question when absent), classifies each clause with its own small cue rules, hands off a misrouted clause and answers a shared clause while also handing it off. It never calls the Coordinator and never scans the full question for other specialists' clauses.
- Why: re-routing would couple specialist and Coordinator, duplicate handoffs for clauses already assigned elsewhere, and make domain decisions inconsistent.
- Revisit: when handoff execution is built in the orchestrator.

## D-035 Chunk-level section eligibility is decided from the headings printed on the page
- Date: 2026-09-28
- Decision: on an in-scope page that also carries a non-owned section, `SectionGuard` attributes each chunk to a section using the section headings printed on that page (number plus the first two title words, located as printed lines and inside paragraph windows) and the chunk order the chunker emits. Text after a non-owned heading is never quoted. A shared page whose headings cannot be located is rejected whole. The page-range `RetrievalScope` is unchanged and remains the first boundary.
- Why: the Step 3.9 gate showed excluded-section text on boundary pages (3.5 on page 80, 12.8 and 12.9 to 12.11 on pages 221 and 222, 5.4 on 117 and 119) becoming supported Teaching findings. Every heading on the fifteen shared pages is printed as its own line, so attribution is reliable without positional guesswork; conservative rejection covers the case where it is not.
- Revisit: if the chunker or the section map changes, or when a chunk-level section label is added to the shared metadata foundation.

## D-036 Relevance requires one anchor concept or two vocabulary concepts; generic words never count
- Decision: the one-content-word rule is replaced by a small explicit Teaching vocabulary with aliases. A quoted unit qualifies when it shares one anchor concept (syllabus, office hours, teaching load, Blackboard, Banner, LMS, attendance, add/drop, final exams and similar) or two vocabulary concepts (exam, grade, teach, course, class and similar) with the focus clause. Generic terms (policy, process, require, contact, fee, assignment, information, faculty, student, university, semester) carry no concept. No stemmer and no calibrated threshold.
- Why: one shared generic word made unrelated fragments supported ("payment of a fixed fee" for a make-up exam fee question) and `not_found` was unreachable. Aliases replace fragile suffix stripping for the small vocabulary that matters.
- Revisit: with measured false negatives on the real cross-encoder; add vocabulary, do not lower the rule.

## D-037 Quote quality rules and sentence units with list-item context
- Decision: headings, numbered list titles, colon-ending lead-ins, lower-case continuations, prose units under five words, truncated last sentences and printed prose lines are not evidence. Paragraph units are sentences; a sentence inside a list item is quoted with the item's opening; a unit is extended by a relevant following unit that does not open a new item. Table rows are quoted whole. Findings are deduplicated by normalised quote on the same page, so a row and its row window yield one finding. The two-findings-per-clause cap is kept.
- Why: heading fragments ("3.1 Teaching Responsibilities", "4. Office hours") and duplicate row and row-window quotes consumed the two finding slots and displaced usable evidence.
- Revisit: at the Teaching QA gate with real ranking; the cap changes only if a real supported question cannot be represented otherwise.

## D-038 The production FINAL_K cut is not applied inside the specialist
- Decision: all reranked candidates above `MIN_RERANK_SCORE` are examined in rank order; the per-clause finding cap bounds the output.
- Why: most chunks are printed lines that the quote rules never accept; cutting to five before the quality rules left no eligible paragraph for common questions. `FINAL_K` limits answer context in the production pipeline, not evidence eligibility.
- Revisit: if candidate examination becomes a measurable cost on the real index.

## D-039 Ownership needs a positive teaching cue; other-domain cues are phrase-level
- Decision: a clause without a teaching cue is not searched (misrouted clauses are handed off, cue-less clauses are reported as unowned). Faculty-services, research and institutional cues are explicit phrases (annual leave, employment contract, research ethics, "who do I contact about", help desk). Bare "contract", "appointment", "benefits", "funding", "extension" and "who approves" are not cues; approval questions about courses stay with Teaching because the curricula-approval policy is Teaching evidence.
- Why: the gate found spurious shared handoffs on ordinary Teaching questions and cue-less questions ("internship requirements") being searched inside the Teaching scope.
- Revisit: alongside the Coordinator's cue tables when handoff execution is built.

## D-040 Calendar lines carry term and academic-year context and are filtered by them
- Decision: for lines on the Academic Calendar pages the term and year are read from the line or the nearest preceding semester header and recorded in the finding; a line from another academic year than the one asked for (default: the registry version's year) or another term than the one named is not evidence; "classes end" is not evidence for "classes begin". Calendar paragraph chunks are not evidence units. No date extractor.
- Why: the gate selected the next year's "Classes begin for Fall 2026-2027" line first and rows lacked semester context.
- Revisit: when a new handbook edition changes the calendar layout.

## D-041 Section labels on findings are page-level and say so
- Decision: every finding carries `section_label_page_level: True`, `page_section_nos`, `shared_page` and `boundary_guard`; `section_no` remains the page's primary section. No more precise number is fabricated; source and page are authoritative.
- Why: on shared pages the primary label can differ from the quoted text's section (12.18.5 text labelled 12.19).
- Revisit: when chunk-level section labels exist in the shared metadata.

## D-042 Paragraph attribution on shared pages is window-independent
- Date: 2026-09-28
- Decision: inside a paragraph window, text after a heading belongs to that heading's section until the next heading, and text before the first heading belongs to the section that precedes that heading in the page's section order. A window without any heading lies in the section the previous window ended in. The region before a heading is never attributed from state remembered by an overlapping window. `SectionGuard` also verifies at construction that chunk metadata ids match list order.
- Why: the Step 3.9B re-test showed that a heading inside the 50-word paragraph overlap let excluded text before it inherit the owned segment reached by the previous window. Windows overlap by more words than a heading marker, so a heading is never missed, and the preceding-section rule attributes every character the same way in every window.
- Revisit: if the chunker's overlap drops below the marker length or chunk-level section labels arrive in the shared metadata.

## D-043 Relevance and completeness are separate gates
- Decision: relevance (one anchor or two vocabulary concepts) establishes the topic only. When a clause explicitly asks for a detail, the clause is fully `supported` only when a finding contains that detail in the same local unit as a clause concept; otherwise it is `partial` and `missing` names the detail. Families: fee or cost, penalty or consequence, deadline or date, number or frequency, minimum, maximum, approving authority, percentage or range, part-time and full-time, location or system, and the faculty category named in the clause. Evidence covering more requested details is chosen first, within a chunk and among candidates.
- Why: one shared anchor made related but incomplete evidence fully `supported` (the full-time office-hours rule for a part-time question, the Regular Faculty load for a research-intensive question). Separating answerability from topic keeps relevance permissive and support honest without a parser or an LLM.
- Revisit: with real-model evidence quality; add families, do not loosen the local-unit rule.

## D-044 Ownership cues are a superset of the Coordinator's teaching cues
- Decision: the specialist's positive teaching cues include every Coordinator teaching cue plus natural phrasings (consultation time and student consultations, class sections and a section being cancelled, first week of classes, timetables, learners, generative tools). Positive ownership remains required; internship, research grant, salary, visa, help desk and parking questions stay unowned.
- Why: a task the Coordinator assigns to Teaching must not be reported unowned because the specialist's vocabulary was narrower.
- Revisit: whenever the Coordinator cue tables change.

## D-045 Antecedent-dependent sentences and tangential procedure evidence
- Decision: a sentence opening with Such, They, These, This, Those or It is quoted with the sentence before it when that sentence is inside the same allowed span and list item and is not a heading; otherwise it is not quoted. For a procedural system request, evidence counts only when it names the system asked about or shares an anchor concept with the request; otherwise the clause is `not_found`. Grade-table lines with textual ranges ("F Below 60 0.00") are table rows. Bare "attend" is plain vocabulary; classroom attendance is the noun, absence, or "attend" applied to classes, lectures, sessions or exams.
- Why: the re-test found antecedent-less quotes, a tangential evening-course sentence making a MyUOS procedure question `partial`, the F grade row rejected, and conference attendance passing as attendance evidence.
- Revisit: at the Teaching QA gate with real ranking.

## D-046 One intent per task is deferred to Coordinator and orchestration work
- Decision: the Coordinator assigns one intent per task and the specialist applies it to every focus clause. Per-clause intents are not addressed in the specialist.
- Why: changing it requires Coordinator and orchestration design, outside the specialist's file boundary.
- Revisit: during Coordinator to Teaching integration (Step 3.10).

## D-047 Requested details are satisfied only within one local evidence unit
- Date: 2026-09-28
- Decision: a clause is fully `supported` only when ONE local evidence unit (a list item, a table row or a sentence) of ONE finding contains every requested detail together with a clause concept. Details found in different units, different findings, different list items or different faculty categories are never combined. `missing` says when a detail is present somewhere but not stated together with the rest.
- Why: the Step 3.9D re-test showed the union of "part-time" from one page-79 item and "five hours" from the other making a part-time office-hours question fully `supported` on the real handbook.
- Revisit: only to add qualifier families; the one-unit rule stays.

## D-048 A quantity is a number tied to a count noun that names the counted subject
- Decision: for "how many", "how much", "number of" and "how long", the evidence unit must contain a number followed by a count noun (hours, credit hours, days, weeks, students, courses, classes, sessions, times, percent, points and similar) whose phrase shares a concept with the counted subject of the question, or its head noun when the subject carries no concept. "How often" is a separate frequency family (weekly, per week, N times). Room, page and section numbers, dates, list markers and counts of something else do not count.
- Why: any number in a relevant sentence satisfied the quantity check.
- Revisit: with real-model probes on numeric questions.

## D-049 Requirement questions need an obligation statement; development and training are anchors
- Decision: questions asking what must be contained, included or provided, what is required or what the requirements are, are answered only by a unit that expresses an obligation (must, shall, required, responsible for, expected to) about the subject. Professional, faculty, teaching or instructional development, development training, training modules, workshops or programmes, training for or of faculty, and "new faculty" are anchor concepts; bare "training" stays plain, so security, safety or compliance training is not faculty-development evidence.
- Why: topic-only questions were `supported` by topically related lines that answered nothing, and sections 3.7 and 5.2 questions were `not_found` by gate rejection.
- Revisit: at the Teaching QA gate.

## D-050 List markers are stripped before the antecedent check; error text hides paths
- Decision: a numbered or lettered list item that opens with a context-dependent word is quoted with the list's lead-in or the preceding plain sentence, never with a sibling item or a heading, and not at all when no such antecedent is inside the allowed span. Error messages in results have key-shaped secrets and filesystem paths (Windows drive paths, home and system trees, other absolute paths) replaced. The section guard's construction-time invariant is unchanged (F-7 stays deferred as documented).

Bare "equal" is no sameness evidence ("a rank equal to or higher than the desired rank" is a threshold, "equal opportunity" a principle), nor is "at the same time"; "equally" and "equal for / across / among / between" remain. "The same field / purpose / academic rank" names another property and never settles the sameness of requirements, procedures or membership. A sentence that refers back to one earlier procedure ("the same procedure mentioned above"), opens with a condition ("If the number ... is less than three, ...") or states an exception ("with the exception that ...") never settles an unconditional, unqualified ask. "Equal pay / leave / benefits" is a sameness ask. (2) Personal decision status. An ask about a decision on the asker's own case is a personal record (`personal_record` kind `status`): grant ("have I been granted", "was I given", "granted to me"), approval ("approved for me", "has my ... been approved", "did HR approve my ...", "my approval status", "is my request still pending", "the outcome of my ..."), acceptance ("has my request been accepted", "did ... accept my") and any other past action or state of the asker's case ("did the committee recommend my promotion", "has HR received my documents", "was I promoted", "who approved my leave"). It carries a detail no unit covers, a missing message and a limitation saying that the handbook holds no personal case or workflow state. A policy ask stays answerable: the mere word "approved / granted / accepted" is not personal ("May unpaid special leave be granted for up to thirty days?", "Who approves termination for cause?"), nor is an eligibility ask ("Can unpaid special leave be granted to me?"), a deontic one ("Was I supposed to ...") or one framed as a condition ("If my leave is approved, ..."). (3) Passive verbs. A passive ask without an agent ("Can the probation period be extended?") for which the shared parser builds no relation binds its verb to the asked subject: some sentence states a form of the verb with the asked subject as the nearest HR anchor before it ("the visiting contract may be extended" never settles the probation period). No personal data source is added and the shared grounding module is unchanged.
- Why: the Step 4.12-R4 confirmation found "Are promotion requirements the same for every rank?", "Is the promotion procedure the same at every college?", "Are the promotion procedures the same at department and college level?" and "Is the promotion committee membership the same for every department?" supported from "equal to or higher", "the same field", "the same procedure mentioned above" and "the same purpose", and "How many days of special leave have I been granted?", "How many leave days were approved for me?", "Has my maternity leave been approved?", "How many days of maternity leave was I granted?" and "Has my promotion been approved?" supported from policy. The Step 4.12-C5 campaign added "Did the committee recommend my promotion?" and the passive class ("Can the probation period be extended?" quoting the visiting-contract sentence; "Can the housing allowance / furniture allowance / salary / end of service compensation be extended?", "Can the probation period be renewed?").
- Revisit: with the Milestone 5 Verifier, if a personal HR data source or workflow system is ever connected, and if the shared parser builds relations for agentless passive asks.

## D-093 A negated condition needs a stated absence, a leave state keeps its polarity, and a passive verb is bound even through a noun relation
- Date: 2026-10-02
- Decision: (1) Condition polarity. A condition the ask states as absent ("without Chancellor approval", "with no notice", "no need for Chancellor approval", "does not require the Chancellor's approval", "the Chancellor's approval is not required", "even if not approved by the Chancellor") carries a `condition` detail that only a sentence stating the same absence covers (a negator such as "without", "no" or "not" before the condition words, or "... is not required" after them). A unit naming the condition as required or given ("with Chancellor approval", "requires the approval of the Chancellor", "must provide a six-month notice", "in special circumstances", "through the HR portal") does not cover it: such evidence contradicts the ask. A true absence stays answerable ("appoint professors with a high Scopus H-index ... without undergoing the regular review"). (2) Leave state. An ask stating the employee's leave state ("has unused vacation leave", "still has vacation leave", "with remaining vacation leave", or "has no unused vacation leave") is settled only by a unit stating the same polarity; "if the employee has no unused vacation leave" contradicts "has unused vacation leave". (3) Exclusions. "Without pay" (and "without full / half pay") is a pay status, bound by the pay-status detail (D-086); "regardless of / irrespective of" is a universality claim (D-091, D-092). Neither is read as a condition here. (4) Passive binding through a noun relation. The D-092 binding of an agentless passive ask ("Can the probation period be confirmed?") now runs whether or not the shared parser built a relation: a relation read from a noun ("employment confirmation includes the probation period" as confirm -> probation period) binds nothing on its own. A verbal form binds the asked subject as the nearest HR anchor before it ("the visiting contract may be extended") or as the object right after an active form ("UoS may terminate faculty contracts"), never after a passive auxiliary or a preposition ("who are terminated during probation"); a noun form binds only through its "of" phrase ("termination of faculty contracts", "renewal of the contract"); a relational verb ("includes", "involves") states no action on its object. The shared grounding module is unchanged.
- Why: the Step 4.12-R5 confirmation found "Can the probation be extended without Chancellor approval?", "Can the visiting contract be extended without Chancellor approval?", "Can faculty resign during probation without notice?", "Can a faculty contract be terminated for cause without the Chancellor's approval?", "Is termination during probation possible without the Dean's approval?" and "Can unpaid special leave be granted when the employee has unused vacation leave?" supported by quotes stating the opposite condition, and "Can the probation period be confirmed?" supported from "Employment confirmation includes the probation period"; the Step 4.12-C6 reproduction added "with no Chancellor approval", "with no notice", "even if the employee still has vacation leave", "without special circumstances", "without submitting through the HR portal", "even if not approved by the Chancellor" and "Can probation be confirmed?", and the C6 campaign found the active-object reading "who are terminated during probation" for "Can the probation be terminated?" before the voice guard was added.
- Revisit: with the Milestone 5 Verifier, and if the shared parser ever reads negated conditions or noun relations itself.

## D-094 Negation governs its own clause, a negated predicate never supports an affirmative ask, leave states read in more words, and an explicit verb is kept
- Date: 2026-10-02
- Decision: (1) Negation scope. A negator in the evidence governs only the words up to its clause break or a new verb phrase (a comma, a semicolon, "may / shall / must / is / are / upon / if / which ..."), at most eight words: in "not exceeding thirty days, may be granted upon approval", "not" governs "exceeding thirty days" and never "approval". The D-093 absence check uses that span; "... is not required / is unnecessary" binds the words right before it within its clause. (2) Absence frames. An ask's absent condition is also read from "need(s) no X", "require(s) no X", "no X needed / required / necessary", "X is unnecessary", "in the absence of X", "despite no X", "absent X" (an approval, consent, notice, recommendation or permission only; "absent from exams" is no condition) and "without needing / requiring X". (3) Evidence polarity. An affirmative yes/no ask claiming a predicate (entitled / eligible as one family, allowed / permitted, based on, impact / affect, part of, included, involved, required) is never settled by a clause that negates the predicate for the asked subject ("new faculty members who resign during probation are not entitled to benefits such as annual leave", "the award shall not impact the monthly salary", "contract renewal is not based on a single year's performance", "associate professors are not involved in reviewing ..."). A structural predicate (based on, impact, part of, included, involved) must be stated affirmatively of the asked subject; an entitlement (entitled / eligible, allowed) is bound wherever the unit uses the word ("may be granted" can state it in other words); "required" is bound by its negation only. The negative rule stays quoted as a finding and the missing message names the negation, so the answer layer can still say "no". This supersedes the D-085 reading that a negative rule supports the affirmative ask and the answer layer reads its polarity. (4) Leave state. Unused vacation leave exists in "vacation leave is unused / left / remaining", "vacation leave remains", "still has (some) vacation leave", "has leave left", "vacation leave has not (yet) been used"; it does not in "no unused vacation leave", "no vacation leave remains / is unused", "vacation leave is exhausted", "has used all vacation leave". The negative phrasings are read first. (5) Explicit verbs. An "is X <action>ed (by Y)" ask ("Is the probation period terminated by the Dean?") binds its action to its subject as the D-092 / D-093 passive binding does, and its agent to the actor of the occurrence (the "by" phrase after a passive or noun form, the subject before an active form; "UoS HR policies" names no agent); the participle must be the main predicate ("Is a terminated faculty member entitled ...", "faculty who are terminated during probation", "new faculty terminated during probation entitled ..." are no passive asks). An active ask whose subject is an HR concept, not a role ("Does employment confirmation extend the probation period?"), binds the verb to the subject before it and the object after it. A relational verb ("includes", "involves", "contains", "covers") never stands for an action. The shared grounding module is unchanged.
- Why: the Step 4.12-R6 confirmation found "Can unpaid special leave be granted with no approval from University authorities?" settled through "not exceeding thirty days, may be granted upon approval", "need no / require no" asks settled by stated requirements, affirmative asks settled by "not entitled", "shall not impact" and "not based on", "vacation leave is unused" unread, and "Does employment confirmation extend the probation period?", "Is the probation period terminated by the Dean?" with their verb dropped; the C7 campaign and breadth rounds added "not involved", "still has some vacation leave", "vacation leave has not been used", "eligible" against "not entitled", "part of" settled by topic overlap, and "terminated by HR" settled by "UoS HR policies".
- Revisit: with the Milestone 5 Verifier (which may restate a "no" answer from a negative rule), and if the shared parser ever reads predicate polarity, negation scope or non-role relations itself.

## D-095 A negative ask is settled only by the same negation, entitlement verbs are one family, each absence frame is read on its own, and a role keeps its verb while a label is no actor
- Date: 2026-10-02
- Decision: (1) Negative asks. A yes/no ask with "not / never / no longer" after its subject claims the negative proposition: a value ("Is the probation period not one year?", "Is the monthly compensation of a dean not AED 10,000?"), a relation ("Is the College Academic Promotions Committee not formed by the College Council?", "Is unpaid leave not deducted from salary?") or a predicate ("Is the basic salary not based on rank?", "Are terminated faculty not entitled to return tickets?"); "no" as a determiner opens one too, as an existence ("Is there no furniture allowance?", "Is no housing provided to faculty?") or after a light verb ("Do faculty get no return tickets?", "Does the award have no impact on the monthly salary?"). It is supported only by a clause that names the asked subject and negates every negated word within the negator's own scope (the D-094 span; a copula right after the negator opens it, as in "shall not be one year"); a negated value stands right after its negator ("is not one year", never "if not completed within one year"). Affirmative evidence ("is one year", "the College Council shall form", "based on faculty rank") contradicts it, and the result is partial with the missing message naming the affirmative. This makes the D-094 contract symmetric; an affirmative predicate followed by "no" ("get no ticket allowances") is no affirmative claim. "Whether / if / or not", a quantity bound ("not more than", "not exceeding"), a negation inside a relative or conditional clause, a contraction ("Isn't ...?") and an absent condition ("does not require X", D-093) are no negative claims. (2) Entitlement synonyms. "Qualified / qualify" join entitled / eligible in the stated family. "Receive(s)", "get(s)" and "(be) given / provided / awarded" are entitlement verbs bound by their negation: "not entitled / eligible / qualified / given / provided / awarded", "ineligible", "disqualified" and "does not receive / get" of the asked subject contradict them, while their affirmative use for another subject ("a shipment allowance is provided") settles nothing either way. For a negative ask the family is one word ("not receive" is answered by "not entitled"). A synonym inside the ask's own condition ("if I receive no notification") or in a relative clause of its subject ("faculty who receive a housing allowance") is no claim. (3) Absence frames. Each "without / with no / no need for / in the absence of / despite" frame ends at the next frame or conjunction: "without pay" stays a pay status and never swallows "without special circumstances", and "without notice and without approval" are two conditions. (4) Role verbs. Extend, confirm, waive, cancel, reduce, increase, revoke, suspend, award, deduct and endorse join the HR action verbs, so "Does the Chancellor extend probation?" keeps its action (the handbook says "with Chancellor approval", so the answer is partial). (5) Labels. Policy, section, chapter, procedure, guideline, rule, regulation, handbook, manual, document, page, form and portal make the role before them a label: "the Chancellor policy", "the HR section" and "committee guidelines" name no actor, and such an ask is supported only when the label itself is stated as the subject of the verb. A reporting frame ("Does the Faculty Handbook say HR provides ...") leaves the role as its verb's subject. The shared grounding module is unchanged.
- Why: the Step 4.12-R7 confirmation found 16 materially wrong supported answers: negative asks settled by the affirmative rule ("not entitled to return tickets", "not based on rank", "not one year", "not 30,000 Dirhams", "not formed by the College Council", "not AED 10,000", "not deducted from salary"), "qualified for" and "get" asks settled despite "not entitled", "without pay ... without special circumstances" read as one pay frame, and "Does the Chancellor policy extend probation?" settled by a termination sentence; the C8 breadth rounds added existential negatives ("Is there no furniture allowance?", "Is there no Hajj leave for Muslim faculty?") settled by the affirmative rule.
- Revisit: with the Milestone 5 Verifier, and if the shared parser ever reads predicate polarity, labels or role actions itself.

## D-096 Semantic consolidation: a specific ask is supported only by a claim compatible on every dimension
- Date: 2026-10-04
- Decision: The HR-local safeguards are consolidated into one claim-compatibility layer (the D-096 block of `faculty_services.py`) instead of one rule per phrasing. A specific yes/no ask is read once as a claim (subject, predicate or action, object, polarity, scope, conditions, population modifiers, value and qualifier) and an evidence clause once as statements (its negations and what they govern, its conditional antecedents and the consequents they condition, the restrictions of its subject); a unit supports the ask only when the two are compatible, and an uncertain compatibility leaves the clause partial. Ten contracts, six of them with a module switch (`_SCOPE_BINDING`, `_CONDITIONAL_FACTS`, `_FRAME_POLARITY`, `_CONDITION_IDENTITY`, `_GENERIC_VERB_FALLBACK`, `_QUALIFIER_IDENTITY`) and the other four in one reader each: (1) Scope: a negative claim is settled only by a negation whose population (appointment basis, track, rank and stage categories; a relative, participle or prepositional restriction of the subject) and object (a modifier before the negated words, a restriction after them) are at least as broad as the asked ones, so "faculty who resign during probation are not entitled ..." does not settle "Are faculty not entitled ...?". (2) Conditional fact: what an "if / when / unless / once / in case / provided that" antecedent states is no fact: a negation inside one negates nothing, and an affirmative claim whose subject and predicate are stated only inside one is not stated ("If the Deans Council approves a promotion, ..." does not settle "Does the Deans Council approve the promotion?"). (3) Negative existence: "Is not any X ...?", "Isn't any X ...?" and "Is there not any X?" are negative existence claims, and an ask opened by a negation claims no affirmative predicate. (4) Labels: a subject phrase holding a label noun, compound or coordinated ("the HR rules and regulations", "HR policy and procedures", "HR guidelines"), names no actor whatever its verb; content verbs ("cover", "include", "state") are left to the named-source contract (D-090). (5) Explicit verbs: the verb after a role subject is kept whether or not the HR inventory knows it ("draft", "exercise"), bound with its actor and object; after "do" or a modal it is bare and no auxiliary follows it, a "be" makes the ask passive, and a generic verb's "for" phrase naming no role is no direction; a comma-delimited consultation or source frame in the evidence ("in consultation with the Chancellor") is no subject. (6) Generic predicate polarity: an explicit negation of the asked predicate for the asked subject, outside any antecedent, contradicts the affirmative ask whatever the predicate ("rendered void", "applicable", "impede", "first resort", "permitted to transfer"). (7) Population modifiers: a relative, participle or "with" modifier of the asked population keeps its polarity ("faculty who are not terminated during probation", "members not meeting UoS standards", "members with a prior appointment"), and a negated modifier is no negative claim. (8) Clausal conditions: a condition stated as a clause ("if the Chancellor does not approve", "when the Chancellor has not approved it", "unless X") keeps its polarity and needs its absence stated as the claim's condition. (9) Condition identity: an antecedent that conditions the asked claim must be the asked condition with the asked polarity; an anaphoric antecedent ("If neither occurs") takes the previous sentence, and each alternative of a disjunctive rule governs its own consequent. (10) Qualifier identity: a value asked with a maximum or minimum is the stated value with that qualifier, and an unmarked value is no maximum when the same item states a larger limit or an extension of the same unit ("one year, extendable to a maximum of two years"). Contracted negation ("n't", ASCII or curly apostrophe) is one negator form across the HR readers. Words are compared by family ("approval" / "approve", "notification" / "notify"). The shared grounding module is unchanged.
- Why: the Step 4.12-R8 confirmation found 43 materially wrong supported answers in ten classes (M1 to M10), 42 of them present before C8: each earlier correction had fixed the phrasings it was shown, and paraphrases outside them passed. The C9 fresh campaign (137 new questions and six dispatch runs) then found two more affirmative claims stated only inside antecedents and two over-blocked true facts, all closed within these contracts.
- Revisit: the C9 breadth sets (90 questions) found wrong supported answers in claim dimensions outside the ten contracts and already present at C8: modal strength (a "must" ask settled by "may", the shared deontic gate accepting any normative marker), universal quantification and affirmative scope ("Are all faculty members eligible ...?", "Are all faculty members entitled to Hajj leave?") and exclusivity ("Is HR the only unit ...?"). Further HR-local rules are not added; an HR-local design review is recommended before any further correction step, and with the Milestone 5 Verifier.

## D-097 HR structured claims: modality, quantifier scope, exclusivity and condition roles are read as one claim, unknown operators fail closed, and a bound contradiction in the returned quote vetoes support
- Date: 2026-10-04
- Decision: A new standard-library module, `handbook_bot/agents/specialists/claim_model.py`, holds the claim and statement schema (polarity, quantifier, modality, condition role, exclusivity focus, compatibility), the operator readers and the compatibility tables; it is deterministic, calls no LLM and imports nothing from the specialists, the shared grounding module, the Coordinator or the dispatcher, and only `faculty_services.py` imports it. The HR specialist reads a specific yes/no question as one structured claim, composing the C1 to C9 readers with these (the asked action, its modality, the asked population and its quantifier, exclusivity and its focus, conditions and their roles, the recognised operators), and adds one detail per dimension, each behind a module switch (`_C10_MODALITY`, `_C10_SCOPE`, `_C10_EXCLUSIVITY`, `_C10_CONDITION_ROLES`, `_C10_OPERATORS`, `_WINDOW_VETO`, `_EXISTENTIAL_SCOPE`; the binding rules behind `_MODAL_BINDING`, `_QUANTIFIER_SLOT`, `_VALUE_EXCLUSIVITY`, `_GENERIC_EXCEPTION_COMPATIBLE`, `_WINDOW_BINDING`). (1) Modality. The asked force (obligation, recommendation, encouragement, permission, possibility, prohibition) must be stated for the asked action: the closest modal marker before the asked verb within its clause and 70 characters (after a leading antecedent the main clause begins at its comma), else a modal-governed occurrence of the asked object. An obligation is answered by "must / shall / required to / requires" and by "should" (D-056), never by "may / can / encouraged" or a bare statement; a permission by permission, recommendation or obligation; a prohibition contradicts every positive ask. "May / can" before an epistemic verb ("may vary", "result in") is a possibility, an "-able" form a permission, "does not require / need not / is not required to" no obligation. A requirement predicate ("Is Chancellor approval required to terminate ...?", "the required documents") and an entitlement ask no modality. (2) Scope. A universal ask ("all / every / each / any") needs an explicitly universal statement at least as broad (`UNIVERSAL_NEEDS_EXPLICIT`, stricter than the approved design table, which let a generic statement answer it); a generic ask needs a statement of the same or a broader population (strict: a restriction or category the ask does not name narrows it, so "female faculty employed on a full-time basis" does not settle "female faculty"); an existential ask ("some / certain") accepts any population of the family, and an existential negative is settled by a narrower negation. The stated population is the subject of a sentence that states the asked predicate and names a person head (a heading or an agentless sentence names none), with its relative clause; light words ("intending", "appointed as", "employed on a ... basis") and negators restrict nothing. Proportional quantifiers fail closed; a time or object quantifier ("each academic year", "all communication") is no population quantifier. (3) Exclusivity. "only / solely / exclusively / sole / just + a number" has a focus (actor, population, object, condition, value, time) and must be stated as exclusive on that focus; a value exclusivity is also met by the exact value with no alternative in the quote (an extension or renewal not negated and not named by the ask itself, or another value of the asked unit); a time or condition exclusivity also by an obligation or a necessary condition on the slot ("only extendable with Chancellor approval"); any other "just" fails closed. (4) Condition roles. "if" is sufficient, "when / once / upon / after" a trigger, "only if / only when / provided that / as long as / subject to / only with" necessary, "unless" an exception, "even if / regardless of / irrespective of" concessive; an approval phrase ("with / upon / subject to ... approval") is necessary and an approval gate. A necessary ask needs a necessary statement; a sufficient ask is not answered by a bare necessary one. The role is read whatever the polarity of the condition's content; for an entity subject ("the probation period") only in a sentence naming it or a pronoun continuing one. A question led by its condition or by an approval phrase is read from its main question; a frequency "once" is no condition. (5) Operators. Every recognised operator has a handler; most / many / few / several, an ambiguous "just", an unqualified comparative and an event order fail closed. (6) Window veto. Support stays local to one unit; a bound contradiction anywhere in the returned quote removes that detail's coverage: a negation of the asked predicate (with the asked object) for the asked population, or for any part of it under a universal ask; an exception to a universal ask; an alternative to an exclusive value; a negation of the asked predicate for the population an asked sufficient condition names ("new faculty members who resign during probation are not entitled to ... annual leave" against "If I resign during probation, am I entitled to annual leave?"). Get / receive / obtain / qualify bind as the entitlement family. A negation inside an antecedent never vetoes, and a stated exception leaves a generic rule standing. Combination is conservative: a contradiction contradicts, else an unknown leaves the clause partial. The shared grounding and evidence modules, Teaching, Research, the Coordinator, the dispatcher and routing are unchanged.
- Why: the C9 breadth sets and the DR1 design review: 11 known wrong supported answers in modal strength, universal scope and exclusivity that the D-096 contracts do not read, and the recommendation to stop patching per phrasing. The C10 implementation keeps all 11 partial with the dimension named under both rankings and the 8 paired controls supported; the fresh campaign (143 new questions, both rankings) found five more wrong supported answers already present at C9 (a generic ask settled by "Muslim faculty attending their first Hajj", "only if" settled by "if", a condition-led ask settled by another clause's affirmative, and two probation asks settled by a sentence about the visiting contract), and the 2,672-question replay one more ("Are faculty members entitled to Hajj leave?"), all closed within these dimensions.
- Revisit: with the Milestone 5 Verifier; if the shared parser reads modality, quantifiers or condition roles itself; the strict universal and generic rules if the source states universality elsewhere (they cost five true universal answers in the campaign and three generic answers in the replay); real-model validation.

## D-098 HR statement-level composite claims: one predicate statement must state the whole claim, every asked operator is consumed by the dimension that evaluated it, and the rest of the returned quote can only veto
- Date: 2026-10-04
- Decision: The D-097 dimensions are evaluated jointly on one predicate statement instead of each on any sentence of a unit. `claim_model.py` (still standard library only, deterministic and imported only by `faculty_services.py`; the D-097 `Claim` and `Statement` types are unchanged) adds the statement-level schema (`PredicateStatement`, `ClaimFrame`, `NounPhrase`, `Anchor`, `Restriction`, `EnumItem`, `TimeFiller`, `LedgerEntry` and the anchor, restriction, frequency and force classes), the closed frequency, hedge, special-circumstance, exception, repetition, waiver and residue lexicons, the force and restriction table and the joint comparison (`compare_claim_to_statement`, `ledger_compatibility`, `first_failure`). (1) Statements. A returned unit is read from its raw text into predicate statements, one per finite clause: a clause breaks at ";" and ":", at "while / whereas / whilst", and at "and / or / but / yet" only with a verb group on both sides (an enumeration such as "Pharmacy, Physiotherapy, Nursing, and Law" is never split); an elided subject is inherited from the clause before; a secondary predication (", extendable to ...", ", renewable ...") stays with its clause; an antecedent ("if / when / unless") is a restriction of the predicate, never a statement of its own; a relative clause stays with its noun phrase; a parenthetical hedge is not bound. A statement is anchored on the asked predicate (its verb, entitlement or predicate word, else its object, else a fallback), at most three anchors per clause; modality, restrictions and frequency bind to the anchored predicate, while the subject, values, enumerations and quantified noun phrases are read on the whole statement. (2) The claim frame. A specific yes/no question becomes the unchanged D-097 claim with its force (first match: universal frequency, universal quantifier, existential, deontic, generic), its asked frequency, its population, its universal noun-phrase slots, its enumeration and its operator ledger; a leading source or level frame that carries no operator ("According to HR policy, ...") is set aside, while "In general" and "Typically" stay as hedges. (3) Joint comparison. A unit supports the claim only when ONE of its statements is compatible on every dimension at once, in the fixed order polarity, subject, predicate, object, modality, scope, frequency, condition, exclusivity, value and time, operator; positive support is never assembled across statements. The C9 polarity contracts, the C9 HR fact reader, the D-097 modal table and the D-097 population-breadth, exclusivity and condition-role readers are reused as they are. An asked actor that is the question's own subject binds by contradiction: a statement whose subject names another role in its head phrase (before its first preposition or relative word) and the asked actor nowhere cannot support it; an agentless, pronoun or entity subject is tolerated, entity identity staying with the C9 contracts. (4) Restrictions. An unconditional claim is unknown against a statement whose predicate carries a restriction its force does not tolerate: an existential claim tolerates every restriction; a generic or deontic claim no necessary condition and no special circumstance; a universally quantified claim also no exception and no hedge; a universal frequency no restriction but a concessive one. A copular attribute ("Is the probation period one year?") is restricted only by a hedge bound to it. (5) Frequency. "Always / in all cases / at all times / every time / automatically" needs an explicit universal frequency in the statement and no restriction; "never" the predicate negated with no restriction; "sometimes" an affirmative statement; "usually / often" the same class restated. (6) Universal slots. "All / every / each" on a population or an object needs an explicit universal over the same head, with modifiers no narrower than the asked ones, no number or cap inside it ("up to three dependent children" states no "all dependent children") and no member exception. (7) Enumerations. An exclusive list is stated only by the same item set, in any order; a subset, a superset or an overlap is unknown. (8) Window vetoes. The other statements of the returned quote bound to the asked predicate can only veto: against an exclusive claim, a repetition of the exclusive value, another time for the same predicate and object (never a relative offset such as "six months before"), a waiver of the exclusive condition, or another actor, population or object marked as additional ("also"); against a universal claim, a member exception or a negation for part of it, and an exception or special circumstance against a universal frequency; against a universal or exclusive claim, a hedge. A veto removes coverage and never adds support. (9) The operator ledger. Every operator of the question (frequency, scope, quantity, restriction, exclusivity, ordering, comparison, conditionality, residue) is recorded with the dimension that must consume it and is consumed only when that dimension actually evaluated it on the bound statement; a residue word ("strictly", "fully", "immediately", "same") only by its literal restatement or a word of its equivalence class (equal, equivalent, same, identical). An unconsumed operator leaves the claim unknown, never contradicted; comparatives, event orders and proportional quantifiers still fail closed through the D-097 operator detail. The composite is one more detail ("claim") of every claim read, required together with the D-097 details; it counts on a unit only together with every other detail of the clause on that same unit, and candidates are ranked by the earlier details first, so it decides support and never which evidence a partial answer reports (a partial answer keeps its units, quotes and D-097 explanation and gains the composite's message). Its missing message names the first failed dimension of the closest statement with its reason and the statement, or the window veto. Nine module switches (`_C11_JOINT`, `_C11_LEDGER`, `_C11_FREQUENCY`, `_C11_SLOT_UNIVERSAL`, `_C11_ENUMERATION`, `_C11_ALTERNATIVES`, `_C11_UNCONDITIONAL`, `_C11_EXCEPTION_WINDOW`, `_C11_FRAMES`), all on. The shared grounding and evidence modules, Teaching, Research, the Coordinator, the dispatcher and routing are unchanged.
- Why: the Step 4.12-R10 confirmation found four wrong supported answers whose universal, exclusive or frequency operator no D-097 dimension evaluated on the sentence that answered them: "Does health insurance cover all dependent children of faculty members?" (the handbook says "up to three dependent children under 18 years old"), "Is the appointment of clinical faculty limited to Medicine and Law?" (the stated list has six disciplines), "Does suspension from duty always result in the suspension of salary?" ("Unless otherwise specified by the Disciplinary Council") and "Do all senior administrative appointments require Chancellor approval?" ("except for Deans, Vice Chancellors, and the Chancellor"). ## D-099 Specific HR claims require structured proof: a specific yes/no claim is supported only through the composite of a read claim and frame on one statement, never by the earlier details alone
- Date: 2026-10-05
- Decision: One HR-local owner, `_specific_claim_support_gate` in `faculty_services.py`, decides the support contract of every clause's claim: SPECIFIC HR CLAIM + NO COMPLETE STRUCTURED PROOF = NEVER SUPPORTED. (1) Boundary. A clause asks a specific claim when it is a yes/no question: led by an auxiliary, led by a phrase or a condition and a comma, embedded in a conversational wrapper ("Hi, ...", "Please ...", "Can you tell me whether / if ...", "I want to know whether / if ...", "Do you know whether / if ...", "Is it true that ...", "..., right?"), led by a negative contraction, or a declarative put as a question; an overview, a what / how / where / who question, a procedure and an open request ("Can you tell me about ...?") are general and keep the C10 / C11 contract unchanged. (2) Wrappers. Greeting and courtesy openers are removed and an embedded or declarative clause is read as the yes/no question it asks (its first auxiliary fronted, else do-support for a finite verb that agrees with its subject; a leading phrase before a wrapper is kept); a semantic operator is never removed. A leading hedge ("In general,", "Typically,", "Usually,") is the claim's frequency operator, so the D-098 frequency dimension needs the same class restated; two frequency operators leave no usable frame; a negative-contraction lead ("Aren't ...", "Cannot ...") and a reported clause ("The handbook says ...?") are unreadable. A lead the Coordinator splits off at a comma ("In general" / "must Deans ...") is re-attached by the HR specialist to the yes/no clause after it. (3) The gate. A specific claim is supported only through the D-098 composite of a read claim and frame; with no claim or no frame its claim detail is one no unit can cover, a unit with no predicate statement never covers the composite, and a specific claim never falls back to the C1 to C10 details. (4) Ledger. No operator of a specific claim is accepted without a check: the D-098 "static" handler is replaced by the dimension that evaluates the occurrence on the chosen statement (a time distributive and a quantity by the value dimension, a universal named only by a modifier by the scope dimension, an event order by its literal restatement, a negative existential by polarity); an operator no dimension reads stays unverified and leaves the claim partial; every asked comparison is an operator of its own. (5) Class A, clause binding. A coordinated clause with a new explicit subject (a pronoun, a role name, or a determiner noun phrase of up to four words) and its finite verb agreeing in number is its own clause ("Professors receive ..., and lecturers receive ...", "... or they email ..."); an enumeration, a bare noun phrase and an elided subject never split, and an ambiguous coordinator keeps the clause whole (no general parser). When a statement of the unit states the asked verb, a clause that only mentions the asked object under its own subject is no statement of the claim; in a sentence of several clauses the asked object is stated in the chosen clause, its list label ("Visiting Appointment: ...") or, for an object pronoun after the verb, the subject of the clause before. (6) Class B, comparisons. Under, over, below, above, less / more / fewer / higher / lower than, at least, at most, no more / less than, not exceeding, up to, equal to and their equivalents are read with their number and unit; a comparison is proved by its restatement, or by one stated value of the same unit that deterministically satisfies it (a plain value, a range, a value with its own bound; another time unit, several values or anything else is unknown), on top of the C9 value reader; a comparison that limits a population ("faculty members over the age of 65", "children under 18") needs its exact restatement. (7) Class C, conditions. For a generic, deontic or universal claim an "if" or "unless" restriction that governs the asked predicate (fronted before it, or inside its main predicate span) leaves the claim partial, as a necessary condition, special circumstances and a non-approval "subject to" already did; an embedded "to determine if", a condition of a secondary predication (", chaired by the dean if a full professor"), the asked condition itself, an asked "unless" and the claim's own content are exempt, and "when" triggers and approval gates stay accepted (D-098); a copular claim meets the same table (the D-098 copular bypass is removed), and so does a negative claim. (8) Class D, modifiers. An important modifier (department, college, university, clinical, visiting, part-time, full-time, new, senior, dependent, academic), on the object or on the subject, must be stated: attached to its head, or for the subject anywhere in the statement, its list label or the acronym of the asked name ("UMC"); another modifier of its family on the head vetoes; a population narrowed by one ("visiting faculty") is not covered by a statement of the unmodified population. (9) Class E, alternative fillers. An exclusive value or object claim is vetoed by another filler of the same slot in the returned quote ("may request additional training leave"; additional / another / further / extra / second / third before every content word of the slot, again / renewed / extended / repeated on either side); an unrelated "additional" never vetoes. (10) A FALLBACK statement (no anchor of the asked predicate in its unit) meets the claim's polarity: a negator of its main predicate (outside its conditions; a predicative "ineligible", "excluded" or "prohibited") cannot prove an affirmative claim, and its absence cannot prove a negative one. Fifteen module switches (`_C12_GATE`, `_C12_WRAPPERS`, `_C12_HEDGE`, `_C12_LEDGER`, `_C12_CLAUSE`, `_C12_OBJECT_ANCHOR`, `_C12_COMPARE`, `_C12_CONDITION`, `_C12_COPULAR`, `_C12_NEGATIVE_CONDITION`, `_C12_MODIFIER`, `_C12_OBJECT_BINDING`, `_C12_ALTERNATIVE_FILLER`, `_C12_LEADS`, `_C12_FALLBACK_POLARITY`), all on. `claim_model.py`, the shared grounding, evidence and details modules, Teaching, Research, the Coordinator, the dispatcher, routing and retrieval are unchanged.
- Why: the Step 4.12-R11 confirmation found 26 materially wrong supported answers (17 on the real fixture, 9 on crafted pages) in six classes: a specific claim with no structured proof falling back to the earlier details (a conversational wrapper or a semantic prefix stopped the claim reader), two coordinated clauses read as one statement, comparisons read as plain values, unconditional claims proved by conditional evidence (copular claims were exempt), important modifiers ignored, and an exclusive value proved despite an additional filler of the same slot. All 26 are partial under both rankings. In the replay of the 2,672 baseline questions, the C10 and R10 campaigns, the R10 analogs, the DR2 probes, the R11 real (279) and synthetic (307) questions and the 128 C11 synthetic questions under both rankings, 43 answers changed, all supported to partial and none partial to supported: 28 correct catches and 15 conservative losses (see `docs/FACULTY_SERVICES_SPECIALIST.md`); no general question changed its status, quotes or message, and no answer changed its quoted evidence. The C12 adversarial transformations then found and closed three more paths: a lead split off by the Coordinator, a population narrowed by a modifier, and a FALLBACK statement negating the claim.
- Revisit: with the Milestone 5 Verifier, which may recover the conservative losses (a hedge prefix of a plain rule, a condition that only adds an eligibility requirement, a nominalised predicate, a time inferred across clauses); if the shared parser reads clauses, nominalisations or roles itself; real-model validation.

## D-100 HR bounded corrections: a specific claim with no role actor and no object binds its asked entity in the supporting clause, and a parenthesised numeral that repeats its number words is normalised before the readers

When the claim reader finds neither a role actor bound to the claim's subject nor an asked object (`_c12_object_roots` empty) and the claim's subject has no population head - a copular or passive ask about an entity, "Is the housing allowance paid once?" - the asked entity is read by `_c12_asked_entity` as the words of the claim's main clause after its leading auxiliary up to the first anchor root, number, number word, comparison operator, verb or exclusivity word, kept as content roots without determiners, prepositions, currency and person words ("the housing allowance"). A claim with a bound actor or an asked object keeps the D-098 subject reader and the D-099 object binding unchanged. ## D-101 HR condition ownership: a restriction is the claim's own content only through the words that distinguish it from its statement's main clause
- Date: 2026-10-24
- Decision: The D-098 own-content exemption `_c11_own` in `faculty_services.py` (a restriction at least half of whose content words are the claim's is the question's own content, not a restriction) is used by `_c11_unasked` - and through it by the D-098 composite condition and frequency dimensions and the D-099 condition dimension - and by the D-099 class-C rule `_c12_material_conditions`. Behind the new switch `_C12_OWN_CONTENT` the same test must also hold on the restriction's distinguishing words: its content roots minus the roots of the statement's main clause (`_c11_main_roots`: the statement text with its restriction texts blanked). A restriction with no distinguishing word is not the claim's own. The rule is monotonic: it can only withdraw a D-098 exemption, never grant one, so it can never make an answer more supported. In `_c11_unasked` a restriction that the D-098 rule exempted and that restates one of the claim's own asked conditions (`_c12_asked_condition`, already used by the class-C rule) keeps its exemption, so a question that states its own condition ("Do faculty members receive a housing allowance if housing is not provided?") is unchanged; the condition dimension still verifies the asked condition's role. The shared claim reader read the condition correctly, but its content roots (housing, university) were half the claim's (housing), so `_c11_own` called it asked content and every restriction check skipped it; the affirmative ("Do faculty members receive a housing allowance?" against "... if housing is not provided") and other-entity variants failed the same way. The Step 4.14-R prototype (distinguishing words only) closed them with no change over the 194 reconstructed cases under both rankings. The implementation adds two safeguards to that prototype: the asked-condition carve-out, so a question that states its own condition is not downgraded, and the monotonic guard, because removing main-clause words raises the share of claim words and could otherwise create a new exemption. ## D-102 HR conditional language: a "when" / "whenever" restriction of the asked predicate is a material condition, as an "if" restriction is (Option A, uniform and fail-closed)

It only adds restriction kinds to the set the condition dimension rejects, so it can withdraw support and never create it. Two expectations move, each with a companion test that asks the condition: "Does the basic salary increase from the following month?" against "When a faculty member is promoted, the basic salary increases from the following month."
